# Security policy

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/tui-project/tui/security/advisories/new) to report suspected vulnerabilities. Do not disclose vulnerabilities in public issues or include exploit details in public pull requests.

Include the affected tui version, installation method, impact, and minimal reproduction steps. Use dummy credentials and redact API keys, tracker passkeys, session IDs, and private URLs. Do not upload your configuration directory or database files.

If GitHub does not show a private reporting option, do not post vulnerability details publicly. You may open an issue asking maintainers to enable private reporting, without describing the vulnerability.

## Supported versions

During early development, security fixes target the latest release. Older versions do not have a separate security maintenance track. Include your exact version in reports so maintainers can assess affected releases.
